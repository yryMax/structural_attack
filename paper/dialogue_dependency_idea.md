# 研究想法：学习虚拟多轮对话中可迁移的依赖结构

记录日期：2026-11-14。状态：候选方向，尚未验证有效性或完整确认新颖性。

## 核心主张与研究范围

多轮注入中值得跨 goal 复用的对象，可能是轮间依赖关系。依据这些关系，为新 goal 生成内容一致的完整对话，可能比跨 goal 固定措辞的模板或单轮局部变异更有效。

> 能否从成功对话中识别具有行为效应的轮间依赖，并把这些依赖用作生成和联合修改的约束，在未见 goal 上提高真实成功率或降低评估成本？

研究对象是**一次工具结果注入中的伪造多轮对话**，候选仍是一整段文本。这与能够读取目标回复、继续施加输入的真实多轮交互策略不同。

## 现有工作的启发

- 有效 ChatInject 多轮基线按具体 goal 使用分别生成的完整对话。
- 当前 turn-search 跨 goal 共用文本，生成器看不到具体 goal，`{goal}` 恰好出现一次，每次只能修改一轮。
- 完整对话可能依赖角色、顺序、问答承接、指代和前提引用共同起效。单轮修改可能破坏这些关系；需要联合修改的结构也未必存在逐步涨分的路径。
- 这些差异提出了“搜索表示可能不合适”的假设；当前失败尚未证明轮间交互存在、可学习或可迁移。

最新 `turn-m3-new` 快照：207 个已评估候选，64 个训练 case、每个重复 2 次，共 26,496 条 trial。根候选为 10/128，训练最佳为 12/128；验证为 7/132，测试为 0/24。205 个完整父子比较有 25 个改善、10 个持平、170 个下降。父节点受到选择，分数存在采样波动，这些比较不能单独证明搜索劣于独立生成。

日志：`../TAP/runs/turn_search/turn-m3-new/`、`../TAP/runs/turn_search/turn-m3-new-select/`。

另外已确认 travel 注入定位漏检：工具文本包含注入，但 Python 字典 repr 形式未被 locator 正确解码，缺失代理反馈。真实 security 检查仍有效。使用代理标签前应修复定位并利用保存的轨迹重判，不能删除 travel 样本后重新定义整体效果。本次只记录想法，没有修复代码或运行新实验。

## 建模：文本关系与实验效应分开保存

### 文本依赖图

```text
Turn(id, role, act, reads, writes, text)
Edge(source, target, relation, variable)
```

- `act`：少量预先约定的行为，如询问、选择、确认、纠正、提出请求。
- `reads/writes`：文本引用、引入或更新的变量。
- `relation`：回答、确认、引用、纠正、使用前提等边类型；行为类型与边类型分开。
- `variable`：关联的信息槽位及相等、不等、集合成员或覆盖关系。

这些字段描述**文本声称的状态**，不能当作目标已接受的状态或模型内部状态。第一版可按整轮建节点；现有篇章解析的 EDU（基本篇章单元）可能比一轮更细，一轮也可能包含多个行为。

同类结构示例：

- A：询问按日期还是主题排序 → 选择主题 → 后续采用主题。
- B：询问输出 CSV 还是 JSON → 选择 JSON → 后续采用 JSON。

两者归一化为：

```text
assistant.ask(x, options=S)
  -> user.fill(x=b, b in S)
  -> assistant.use(x=b)
```

不同结构示例：提出输出 JSON → 用户要求改为 CSV → 后续改用 CSV。

```text
assistant.propose(x=a)
  -> user.correct(x=b, b != a)
  -> assistant.revise(x=b)
```

判同规则：统一重命名变量后，角色、行为、边类型、依赖顺序及变量绑定模式一致。第一版生成规范化签名，复杂结构再比较带类型的图同构。

必须保留“同一个值、不同值、引用哪个集合、覆盖哪个旧值”，不能全部压成一个槽位。区分整段结构相同与共享依赖子结构；额外轮次也不能默认没有行为作用。同类文本结构不保证功能等价，效果能否迁移必须另测。

语义对齐需要现成解析器、人工或 LLM，模糊项保留为未知。仅凭 ASR 无法恢复语义关系类别。

### 实验交互表

另行记录：轮组、干预文本、case、重复编号、真实成功、效果与不确定性。文本依赖图首先是待检验假设，不能与实验表混成“已知因果图”。

对不包含必要 goal 内容的候选块 A、B，固定其余上下文，比较都保留、只保留 A、只保留 B、都使用控制内容：

```text
I_AB = p11 - p10 - p01 + p00
```

`p` 为对应条件下的真实成功率。该量依赖背景和概率尺度，是对称的，不能推出 A→B；顺序效应需另外测。正交互只支持局部非加性，不能直接宣称已恢复高阶依赖或内部机制。

## 方法流程与分工

1. 在训练数据中挑少量能够独立复现的成功种子，结合失败样本提出少数关系候选。
2. 借用现成关系标签，由解析器、人工或 LLM 提出边及变量绑定，并人工核对小样本。
3. 用实际文本干预和目标 rollout 检验候选关系，保留 goal 与行动要求，控制上下文、长度、位置及 renderer。
4. 将有可重复效应的关联轮组作为联合生成／修改单位，并记录适用条件。
5. 新 goal 到来时按结构生成具体内容。变量改变时，同步更新依赖该变量的片段。
6. 冻结结构与生成流程，在未见 goal 上评估；实例化信息遵守同一威胁模型，不使用 held-out 反馈继续修改结构。

分轮、角色、goal 定位和结构匹配由程序完成；语义候选可由解析器或 LLM 提出；生成由 LLM 完成；关系是否有用由实际行为与环境检查判断。A/B/C 只做诊断，不承担关系有效性和最终成功的证明。

第一版只需节点表、边表、干预结果表和联合改写操作。是否训练新网络或引入更复杂搜索，由小实验决定。

## 最小验证实验

回到已确认多轮有效的模型与设置，先独立复现少量成功基线，再在训练 case 上做：

- A、B 的四格比较，其中包含原完整结构。
- 相关轮次的顺序交换；加入无依赖轮组的重排对照，检查位置和近因效应。
- 保持依赖关系的措辞改写；必要时测试变量绑定的保持与破坏。

可用“8 个训练 case × 约 6 个条件 × 2 次重复 ≈ 96 次 rollout”作为粗略先导预算，条件需随结构调整。它只能筛选方向，不能承担论文显著性结论。

删一轮同时改变长度和语义，不能只凭下降断言依赖。删 JSON 边不会改变模型输入，每项干预都必须落实成实际文本，配合等长中性替换等控制。

## 对照、成本与结论边界

后续比较：同训练示例的独立完整生成／few-shot best-of-N、当前单轮搜索、普通多轮块修改、依据实验支持的依赖约束生成／修改。还需“破坏所学约束”的消融。

匹配目标信息、示例、模型、renderer、长度、选择流程和目标调用预算，同时报告 token 与时间。依赖提取的训练成本必须计入，不能只比较迁移阶段。通用模板与 goal 条件生成分开比较，防止信息量差异被当成算法收益。

使用同 case 配对比较，进行独立生成／搜索重复；不能把同一 case 的 repeats 当成完全独立样本。最终使用未参与设计调参的 held-out 数据。

- 没有稳定结构效应：不支持当前关系假设。
- 有局部交互、无迁移增益：支持有限结构效应，不能宣称迁移算法有效。
- 有迁移增益、缺机制证据：可以报告效果，机制解释保持开放。
- 仅胜过单轮修改，未胜过普通块修改：收益可能来自扩大修改单位。
- 稳定胜过同示例生成和普通块修改，破坏关系后又失去收益：才支持“识别依赖—复用依赖—获得收益”的完整链条。

## 候选 novelty

[ChatInject](https://arxiv.org/abs/2509.22830) 已覆盖聊天模板角色伪造、虚拟多轮及迁移；[PHANTOM](https://arxiv.org/abs/2602.16958) 已覆盖结构模板增强与自动搜索；[Prompt Injection as Role Confusion](https://arxiv.org/abs/2603.12277) 已覆盖角色机制分析。依赖图和流程图本身也已有成熟研究。

候选贡献应落实为：**在虚拟多轮注入中识别有可迁移行为效应的依赖，据此生成或联合修改，并证明相对于匹配对照的额外效果或成本收益。** 当前 TAP 失败只提供动机。有效性和首创性仍待验证。
